# Career Quest — этап 1: продуктовый контракт

Статус: черновик для согласования командой. Реализация интерфейса и recommendation engine начнётся после утверждения.

## 1. Продукт

Рабочее название: `Career Quest`.

Подзаголовок: `AI-навигатор развития сотрудника`.

Пользовательская ценность: сотрудник понимает, какой следующий шаг развития выбрать, почему он подходит именно ему и как этот шаг приближает его к следующему грейду.

Ценность для HR: компания видит общую картину дефицитов навыков и вовлечённости, а развитие сотрудников перестаёт быть набором разрозненных уведомлений.

## 2. Пользователи

### Сотрудник

Видит только собственный профиль, карьерную цель, навыки, историю активностей и персональные рекомендации. Может отметить активность выполненной и посмотреть изменение прогресса.

### HR или руководитель

Видит агрегированный срез по сотрудникам, ролям, грейдам, навыкам и активностям. Персональная история сотрудника не должна быть доступна другим сотрудникам.

## 3. Обязательный сценарий MVP

```text
выбрать сотрудника → увидеть цель и gaps → получить 1–3 шага
→ открыть доказательное объяснение → отметить активность выполненной
→ увидеть обновлённый прогресс
```

Доказательное объяснение должно использовать несколько входных факторов: текущий и целевой грейд, конкретные разрывы по навыкам, требования целевого уровня и историю участия.

## 4. Границы первой версии

В первую версию входят:

- загрузка стартового JSON/CSV-датасета;
- поддержка дополнительных профилей в той же схеме;
- профиль сотрудника;
- расчёт карьерной цели и gaps;
- фильтрация активностей по роли, грейду и prerequisites;
- ранжирование 1–3 следующих шагов;
- объяснение рекомендации;
- обновление прогресса после выполнения;
- компактный HR-view.

Не входят в обязательный MVP:

- лидерборды и публичные рейтинги;
- внутренняя валюта и магазин наград;
- прогноз оттока;
- интеграции с мессенджерами и календарём;
- полноценная мобильная версия;
- сложная ролевая система авторизации;
- генерация нового контента обучения.

## 5. Визуальная система

Референс — визуальная система Halyk из предоставленных материалов: зелёный как основной цвет продукта, жёлтый как акцент, светлые поверхности и графитовый текст.

Рабочая палитра до получения официальных дизайн-токенов:

| Роль | Цвет | Использование |
|---|---|---|
| Основной зелёный | `#008C72` | кнопки, активное состояние, ссылки, прогресс |
| Глубокий зелёный | `#006F5B` | hover и тёмные акценты |
| Жёлтый акцент | `#F5B51B` | маркер цели и небольшие выделения |
| Светлая поверхность | `#F7F8F7` | фон приложения и вторичные области |
| Белый | `#FFFFFF` | основные панели и карточки |
| Графит | `#1F2926` | основной текст |
| Вторичный текст | `#6D7773` | пояснения и метаданные |
| Ошибка | `#C94A4A` | ошибки загрузки и недоступные действия |

Палитра является рабочей интерпретацией референсов, а не заявлением об официальных брендовых токенах. После получения брендбука значения можно заменить централизованно.

Принципы интерфейса:

- спокойный корпоративный вид без неоновых градиентов;
- один главный акцент на экране;
- короткие подписи вместо рекламных лозунгов;
- объяснение рекомендации важнее декоративной аналитики;
- графики только там, где они помогают принять решение;
- не использовать слово `AI` в каждом блоке интерфейса;
- избегать публичного сравнения сотрудников между собой.

## 6. Технологическое решение

Базовый вариант: Python + FastAPI + Jinja2 + CSS/JavaScript. Это позволяет собрать полноценный веб-интерфейс с одной командой запуска и не тратить время на отдельную frontend-сборку.

AI-модель используется для формулировки объяснения поверх рассчитанных системой фактов. Само решение о том, какие навыки проседают и какие активности допустимы, должно быть воспроизводимым кодом.

## 7. Точки согласования перед этапом 2

- название `Career Quest` и подзаголовок;
- два режима: сотрудник и HR;
- границы обязательного MVP;
- рабочая палитра и общий визуальный характер;
- FastAPI + Jinja2 + CSS/JavaScript;
- использование LLM только поверх структурированных доказательств.
